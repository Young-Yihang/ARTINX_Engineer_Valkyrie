# ARTINX Engineer Valkyrie

  > 是的，这是一个ARTINX的机械臂项目，该项目稳定可靠的服役完成了RM2026的分区赛，以及国赛
  >
  > 算是作者对于2025时期刚入队时，工程机器人没上单片机做出的正面回答。

  ## 如果你是现役RMER

  这个框架包含大量初始设计不成熟&vibe&本人坚持，并不像其他电控框架&视觉框架一样面向可读性（也许可能其实很可读），也没有把多进程改成线程管理，如果想学建议看看别的开源

  ## 如果你想跑个仿真

  项目根目录三个bash脚本足够了，vibe给足了提示，环境请用rosdep自查，并且具备mujoco和moveit等环境，由于数组长度处理没push，仿真现在有大量报错而且无法机械臂无法正常动

  ## 这台臂里有什么

  集成了不少内容，包括一开始的moveit学习痕迹，gazebo/mujoco的仿真可行性验证

  ## 感谢的人

  任务调度节点是参考去年的下位机工程代码框架编写的，2024带我的熊学姐真的超有耐心，以及贡献下位机框架的马哥和杰哥，没有你们我难以抱有如此热爱坚持着自己做完这些

  ## 一点设计想法

  思来想去用什么算法服务于比赛，比如25自己第一年在下位机造了一套基于pieper构型的解算，把边界条件都收敛的不错，一年就做到了绝佳的成绩，今年尝试着把下位机的一些算法搬上来，但是发现对于
  今年的规则不太适合离线写期望位姿->直线规划的做法（因为取出位姿太多了），最后和claude vibe出了一套调试前端，基于moveit现成的插值规划器和示教记录，可以在关键点手动保存后规划实现离线轨
  迹，这一套能保证我们的取矿&存矿在机械臂自身运动调得好的前提下可以一晚上搞定所有基础功能，有分区赛的顶级成绩作证

  以及动力学是否在上位机这些问题，还有链路稳定性问题，为什么在前馈+同一套pid解算端在上/下位机的时候关节表现不一致（甚至尝试过让上位机也频率相同。。？算是当时没有系统学过机器人的架构设计层导致的问题）种种问题，最终在一点思考和有但是
  没那么好的品味下，这个代码仓库最终呈现成了这样
