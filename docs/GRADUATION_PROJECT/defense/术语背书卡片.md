> 格式: **术语** → 一句话解释 → [如果追问] 补充细节

## A. 运动学 & 动力学

**D-H参数法 (Denavit-Hartenberg)**
→ 用4个参数(α, a, d, θ)描述相邻关节坐标系之间的变换关系，是建立机器人运动学模型的标准方法。
→ [追问] 我的6轴臂用改进D-H，每个关节一组参数，正运动学就是6个齐次变换矩阵连乘。

**位姿解耦**
→ 把6DOF逆运动学拆成"前3关节解位置 + 后3关节解姿态"两个独立子问题，降低计算复杂度。
→ [追问] 前3关节用几何投影法解腕部中心点坐标，后3关节对旋转矩阵做ZYZ欧拉角分解。之所以能解耦是因为后3轴交于一点（球腕结构）。

**正/逆运动学 (FK/IK)**
→ 正运动学：已知关节角求末端位姿。逆运动学：已知目标位姿求关节角。
→ [追问] FK是矩阵连乘有唯一解，IK一般有多组解（我的最多8组），选最近解。

**动力学前馈**
→ 根据动力学方程 τ=M(q)q̈+C(q,q̇)+G(q) 直接计算理论上需要的力矩，让PID只需要补偿模型误差，而不是承担全部控制量。
→ [追问] M是惯性矩阵、C是科氏力+离心力、G是重力项，用KDL库基于URDF实时计算，<1ms。

**M(q)、C(q,q̇)、G(q) 分别是什么？**
→ M: 惯性矩阵(质量矩阵)，描述加速度需要多大力矩
→ C: 科氏力+离心力矩阵，旋转时产生的耦合力
→ G: 重力矩阵，抵消重力需要多大力矩
→ [追问] 在HOLD模式下只补偿G(q)就能让机械臂静止不掉。

**KDL (Kinematics and Dynamics Library)**
→ 开源运动学和动力学库，属于Orocos项目，能从URDF自动解析关节链并计算M/C/G矩阵。
→ [追问] 内部用递归Newton-Euler算法，计算复杂度O(n)。

**URDF (Unified Robot Description Format)**
→ ROS标准的机器人模型描述格式，XML定义关节、连杆、惯性参数、碰撞体等。
→ [追问] 我的URDF里6个旋转关节+1个棱柱关节(夹爪)，MoveIt2和MuJoCo都从同一份URDF生成。

## B. 控制算法

**级联PID (Cascade PID)**
→ 两层嵌套的PID：外环P控制位置误差输出参考速度，内环PI控制速度误差输出力矩。好处是内环响应快能抑制速度扰动。
→ [追问] 外环只用P(+条件积分)，内环用PI，所有Kd=0。不用D是因为速度信号本身噪声大，D会放大噪声。

**为什么外环也加了积分？**
→ 消除重力等造成的稳态位置误差。但做了条件积分——只在误差<0.1rad时才积分，防止大误差时积分饱和。

**抗积分饱和 (Anti-windup)**
→ 防止积分项在大误差或饱和时无限增长导致超调。我用了三重措施：条件积分、积分限幅、急停时清零。
→ [追问] 条件积分: 误差>0.1rad时不积分; 限幅: max_integral夹住; 急停: 模式切换时清零。

**力矩控制 vs 位置控制**
→ 位置控制直接发目标角度给电机驱动器，简单但刚性大。力矩控制发目标力矩，能实现柔顺性——重力补偿、拖动教学、接触力控制。
→ [追问] 力矩控制的难点在于需要准确的动力学模型和状态估计，但好处是可以做FREEDRIVE模式让人直接推着机械臂教学。

**4种控制模式的区别？**
→ RELAX: 零力矩，电机不出力（上电默认安全态）
→ FREEDRIVE: 只补偿重力G(q)，人可以徒手推动
→ OVERDRIVE: 重力+PD反馈，锁住当前位置不动
→ EXECUTE: 全前馈M+C+G加PID，跟踪轨迹

## C. 状态估计

**速度后处理滤波 / 为什么需要滤波？**
→ 电机编码器测得的速度信号有高频噪声（量化+采样抖动），直接喂给PID的话D项和速度PI都会输出剧烈抖动。滤波平滑后控制输出更稳。
→ [追问] 实现上是对编码器速度做滤波，Q和R参数支持运行时通过ROS2 param热调。

**为什么不用互补滤波或低通滤波？**
→ 都可以，实际效果差不多。关键是要平滑速度、相位延迟小。当前方案在200Hz下已经够用。

## D. 通信协议

**Seasky协议**
→ 自定义轻量级串口协议。帧结构: SOF(0xA5) + 长度 + CRC8(头校验) + CmdID + 数据 + CRC16(全帧校验)。
→ [追问] 为什么不用Modbus/CAN-over-serial? 因为这是我们团队嵌入式侧已有的成熟协议，8字节头开销很小，CRC双校验保证可靠性够了。

**CRC8 和 CRC16**
→ CRC8校验帧头4字节（快速检测头部损坏丢弃），CRC16校验整帧（保证数据完整性）。双重校验。
→ [追问] 用查表法实现，不额外耗CPU。

**921600波特率**
→ 约92KB/s，一帧最大100多字节，200Hz发送毫无压力。比115200快8倍。
→ [追问] USB虚拟串口实际速率不受波特率限制（USB2.0理论480Mbps），但MCU侧UART是真实波特率。

**CAN总线**
→ MCU到电机之间的通信总线。1Mbps，差分信号抗干扰。DJI/达妙/瓴控三种电机都走CAN。
→ [追问] 一条CAN总线挂多个电机，通过不同ID区分，广播式收发。

## E. 仿真 & 工具链

**MuJoCo (Multi-Joint dynamics with Contact)**
→ DeepMind开源的物理仿真引擎，擅长接触动力学。输入力矩/力，仿真出物理运动。
→ [追问] 相比Gazebo精度更高、接触仿真更稳定。从URDF自动转成MuJoCo的XML格式。

**数字孪生 (Digital Twin)**
→ 真机运行时，MuJoCo只做3D渲染不做物理仿真(visualization_only=true)，用真机反馈的关节角驱动3D模型，实时同步显示。
→ [追问] 好处是真机运行时有3D可视化监控，遇到问题能直观看到姿态。

**ImGui / ImPlot**
→ 即时模式GUI库，叠加在MuJoCo渲染窗口上，实时显示参数面板和曲线图。
→ [追问] ImGui做参数调节滑块，ImPlot画位置/速度/力矩的实时曲线，类似示波器。

**MoveIt2**
→ ROS2的运动规划框架，负责路径规划、碰撞检测、IK求解。
→ [追问] 我用它做轨迹生成，输出的是关节轨迹(位置+速度+加速度)，然后交给我的力矩控制器执行。

**Pilz Industrial Motion Planner**
→ MoveIt2的一个规划器插件，支持LIN(直线)和PTP(点到点)两种笛卡尔运动。工业级确定性规划。
→ [追问] LIN是末端走直线到目标，PTP是关节空间最短路径。LIN失败时自动降级为PTP。

**ROS2 Jazzy**
→ ROS2的2024年LTS发行版。相比ROS1改用DDS通信，支持实时性。
→ [追问] DDS(Data Distribution Service)是工业标准中间件，发布-订阅模型，QoS可调。

**Topic / Service / Action 区别？**
→ Topic: 发布-订阅，持续流式数据（如joint_states 200Hz）
→ Service: 请求-响应，一次性调用（如gripper_control）
→ Action: 长时间任务+反馈+可取消（如follow_joint_trajectory轨迹执行）

## F. 硬件

**J8009 / GM6020 / J4310 / M2006**
→ 都是RoboMaster生态常用电机。J8009是达妙大扭矩(40Nm)，GM6020是DJI云台电机(1.2Nm)，J4310是达妙中型(7Nm)，M2006是DJI小电机(1Nm)。
→ [追问] 为什么不统一用一种? 因为各关节负载差异大，近端要大力矩，远端要轻量化减惯量。

**棱柱副 (Prismatic Joint)**
→ 直线运动关节，对比旋转关节。夹爪的两个爪片沿导轨直线滑动。
→ [追问] URDF里type="prismatic"，行程0-40mm，MuJoCo里力的单位是N不是Nm。

**麦克纳姆轮 (Mecanum Wheel)**
→ 轮面上有45度斜辊子，4轮组合可实现全向移动（前后左右+旋转）。
→ [追问] 运动学解算就是4×4逆矩阵，输入目标vx/vy/ω输出4个轮速。已在STM32实现。

## G. 视觉伺服 (后续计划，准备被追问)

**YOLOv8**
→ 实时目标检测网络，可以检测图像中矿石的位置(bounding box)。
→ [追问] 打算用预训练模型fine-tune自己的矿石数据集。

**PnP (Perspective-n-Point)**
→ 已知物体3D特征点和对应的2D像素坐标，解出相机到物体的6DOF位姿(R,t)。
→ [追问] OpenCV有solvePnP函数，输入至少4个点对就能求解。

**手眼标定 (Eye-to-Hand)**
→ 求相机坐标系和机器人基座坐标系之间的固定变换矩阵T。标定后视觉检测到的位姿可以直接转换到机器人坐标系。
→ [追问] Eye-to-hand: 相机固定在外部看机器人; Eye-in-hand: 相机装在末端随臂运动。我用eye-to-hand。

**PBVS / IBVS**
→ PBVS(Position-Based): 视觉算出目标位姿→规划笛卡尔路径→执行。IBVS(Image-Based): 直接用图像特征误差做闭环。
→ [追问] 我打算先用PBVS，因为已经有cartesian_controller可以直接用，20Hz够了。

**视觉伺服接口怎么接？**
→ cartesian_controller已预留Topic接口(/cartesian_target_pose)，20Hz上限。视觉节点发目标位姿，控制器规划并执行。50ms最小间隔防止规划器过载。
